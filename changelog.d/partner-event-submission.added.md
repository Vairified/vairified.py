`client.events.submit()` puts one of your own events into the Vairified directory. Vairified shows the event and sends players to your registration page; no registration and no payment happens on Vairified, and no player data comes back to you through this call. Re-submitting is how you edit: the listing is addressed by `partner_event_id` — your own identifier, not Vairified's — so submitting the same one again updates the listing in place rather than creating a second one, and `created` on the result tells you which happened. Identifiers are scoped to you, so another partner using the same string is a different listing and neither of you can affect the other's. One submission is one place at one time: an event running at four venues is four submissions, each with its own `partner_event_id`, coordinates and `registration_url`, because one row for four venues puts a single pin on a map for an event happening in four places. `latitude` and `longitude` go together — one without the other is rejected, since a listing with half a coordinate cannot be placed and would never appear in a radius search. Only `TOURNAMENT`, `LEAGUE` and `OPEN_PLAY` may be submitted, and every listing is tagged as third-party: a submitted event cannot be made to look like one Vairified runs itself. Adds the frozen model `SubmittedEvent`. Requires the `key:event:submit` scope, granted per partner on approval and not implied by `key:write` or `key:admin`, plus an API key linked to your partner application.
