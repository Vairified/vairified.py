`client.events.submit()` now requires `sport_code`, with deliberately no default. A submitted event carries no sport of its own, so before this every listing read as whatever the directory assumed — which for Vairified means pickleball, and a padel event surfacing as pickleball is a multisport isolation failure visible to the public. It is required rather than defaulted because a default is how the wrong sport gets in quietly, and an unknown code is rejected rather than falling back. `client.events.list()` also validates its filters instead of ignoring them: an unrecognised `type` is a 400 rather than a silently dropped filter, since a dropped filter returns the whole catalogue and looks exactly like a working request; and `radius_miles` is bounded at 250, matching the cap the internal events search enforces, with a larger radius rejected rather than narrowed.
